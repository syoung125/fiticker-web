# 유지보수 가이드

## 어디를 수정하나요?

| 바꾸려는 것                            | 수정 위치                          |
| -------------------------------------- | ---------------------------------- |
| 페이지 문구, 입력 필드, 화면 구조      | `index.html`                       |
| 컬러, 여백, 카드 모양, 반응형 스타일   | `src/styles/main.css`              |
| 운동 카테고리, 이모지, 색상            | `src/domain/workouts.js`의 `TYPES` |
| 주 계산, 시간 표시, 입력 제한          | `src/domain/workouts.js`           |
| 시간 휠 UI·키보드 선택                 | `src/ui/duration-picker.js`        |
| 분 단위 선택지·휠 행 계산              | `src/domain/duration-picker.js`    |
| 캘린더와 기록 카드 출력                | `src/ui/render-editor.js`          |
| 입력/수정/삭제, 주 이동, 미리보기 흐름 | `src/app.js`                       |
| 공유 이미지의 제목·색상·배치           | `src/media/poster.js`              |
| 사진 용량 제한, 리사이즈 크기          | `src/media/photo.js`               |
| 개발 포트, 빌드 경로                   | `vite.config.js`                   |
| 자동 검사·배포 조건                    | `.github/workflows/deploy.yml`     |

코드에 들여쓰기와 줄바꿈이 적용되어 있습니다. `npm run format`으로 같은 스타일을 유지하세요.

## 데이터 흐름

`src/main.js`가 CSS와 앱을 로드합니다. `src/app.js`가 현재 주와 기록을 메모리에 보관합니다. 저장 시 `validateRecord()`가 입력을 검증하고, `renderEditor()`가 그 상태를 받아 캘린더·합계·카드를 다시 그립니다. 이미지 생성은 현재 주의 날짜와 기록을 복사한 뒤 `createPoster()`에 넘깁니다. 생성 도중 주를 바꾸더라도 결과 이미지와 다운로드 파일명이 일치합니다.

기록 구조:

```js
const records = {
  '2026-10-01': {
    type: 'running',
    name: 'Running',
    minutes: 45, // 미입력은 null. 0과 구분합니다.
    memo: '가볍게 5km',
    photo: null, // 또는 브라우저에서 축소한 JPEG data URL
  },
};
```

현재는 날짜 하나가 기록 하나의 키입니다. 하루 여러 운동이나 영구 저장을 추가하려면 이 모델과 합계·렌더링·이미지 생성·테스트를 함께 변경해야 합니다.

## 종목별 시간 합계

공유 이미지에는 현재 주에 두 종목 이상 기록한 경우에만 총 시간 오른쪽에 종목별 합계를 표시합니다. 같은 종목은 합산하고, 기타 종목은 입력한 이름으로 구분합니다. 모든 기록에 시간이 없는 종목은 `시간 미입력`으로 표시하며, 시간이 있는 기록과 없는 기록이 섞이면 입력한 시간만 합산합니다. 집계는 `src/domain/workouts.js`의 `summarizeBySport`, 배치는 `src/media/summary.js`에서 수정합니다. 입력 화면의 합계·작은 미리보기·최종 PNG는 이 공통 렌더러를 사용하므로 정렬과 표시 내용이 같습니다. 종목명은 왼쪽, 시간은 오른쪽 정렬이며 긴 이름은 말줄임 표시합니다. 전체 이름은 일별 카드와 접근성 설명에 유지됩니다.

## 시간 선택 휠

시간은 0~23, 분은 0~55를 5분 단위로 선택합니다. 가운데 행이 선택값이며 스크롤·클릭·방향키를 지원합니다. 처음 열면 미입력 상태이며 `선택 해제`로 미입력으로 되돌릴 수 있습니다. 기존 기록에 7분처럼 5분 단위가 아닌 값이 있으면 해당 값을 선택지에 추가해 보존합니다.

휠 행 높이는 CSS의 `--wheel-row-height`와 `src/domain/duration-picker.js`의 `WHEEL_ROW_HEIGHT`를 함께 수정합니다. 휠 위치는 입력 모달을 연 다음 초기화해야 합니다.

## 이미지 레이아웃

`poster.js`는 웹 화면을 캡처하지 않고 별도의 Canvas에 그립니다. 크기는 1080 × 1920이며, 1~4개 기록은 2열, 5~7개는 3열입니다. 사진이 없으면 카테고리 이모지와 배경색을 사용합니다. 폰트 다운로드 실패 시 기본 글꼴로 계속 생성합니다.

메모 길이, 글자 크기, 카드 수를 바꾸면 7개 기록과 긴 한국어 메모로 이미지 넘침을 확인하세요.

## 수정 후 확인

```sh
npm run format
npm run check
npm run preview
```

실제 브라우저에서도 다음을 확인하세요.

1. 운동 종류만 선택해 저장: 횟수 1, 시간 0m.
2. 다른 날짜에 1시간 30분 추가: 횟수 2, 시간 1h 30m.
3. 기존 기록 수정·삭제, 이전/다음 주 이동 후 데이터 확인.
4. 기타 운동명, 한국어·이모지 메모, 사진 첨부·삭제.
5. 7일 모두 입력 후 PNG 저장: 1080 × 1920, 모든 기록 표시.
6. 모바일 세로 화면에서 모달 스크롤, 키보드 입력, 이미지 저장.
7. 새로고침 시 빈 기록으로 초기화.

브라우저 UI 도구의 정책 확인 오류로 최초 자동 화면 검증은 수행하지 못했습니다. 단위 테스트·빌드·배포 성공과 실제 기기 화면 검증은 구분해서 관리하세요.

## 배포 흐름

`main` push → 의존성 설치 (`npm ci`) → 포맷·테스트·빌드 (`npm run check`) → `dist/` 업로드 → GitHub Pages 배포.

저장소에는 원본과 설정·테스트·문서를 올립니다. `dist/`나 `node_modules/`를 직접 수정하거나 커밋하지 않습니다. 별도의 배포 토큰을 저장할 필요는 없으며 GitHub Actions의 기본 토큰을 사용합니다. 쓰기 권한은 배포 작업의 Pages 권한으로 제한됩니다.

## 문제 해결

- **설치 실패**: Node 버전을 확인하세요. `.nvmrc`에 맞춰 Node 22 최신 버전을 쓰고 `npm ci`를 다시 실행합니다.
- **포트 사용 중**: `npm run dev -- --port 5175` 또는 `npm run preview -- --port 4175`로 실행합니다.
- **HTML 파일을 직접 열면 안 됨**: ES 모듈 앱이므로 `npm run dev` 또는 `npm run preview`의 URL로 접속합니다.
- **배포 실패**: GitHub Actions의 실패한 단계 로그를 확인합니다. Pages Source가 GitHub Actions인지 확인하세요.
- **수정이 사이트에 안 보임**: 해당 커밋의 배포 완료를 확인하고 브라우저를 새로고침합니다.
- **의존성 추가/업데이트**: `npm install`로 변경 후 `package.json`과 `package-lock.json`을 함께 커밋합니다.

## 작업별 바텀시트

날짜의 + 버튼은 종목 선택만 엽니다. 기본 종목을 누르면 종목을 저장하고 선택적 시간 입력으로 이어집니다. 시간 없이 완료하거나 시트를 닫아도 종목은 유지됩니다. 기타 종목은 이름 입력 후 같은 흐름으로 이어집니다. 카드의 시간·종목·메모·삭제 버튼은 각각 하나의 작업만 보여줍니다. `src/ui/record-sheet.js`가 시트와 임시 입력을 관리하고, `src/domain/record-actions.js`가 해당 필드만 갱신합니다. 닫기나 바깥 영역 클릭으로 취소하면 기존 기록은 유지됩니다. 사진은 바텀시트 없이 파일 선택창에서 바로 첨부합니다.

사진 추가·변경은 `src/ui/photo-picker.js`에서 파일 선택창을 바로 열고 선택 즉시 저장합니다. 사진 삭제는 카드에서 실행합니다. 날짜별 처리 버전을 관리하므로 늦게 처리된 사진이 새 선택이나 삭제를 덮어쓰지 않습니다.

## 스티커 출력

기록 아래에 요약(연두색 카드)과 주간 캘린더(투명 배경)를 독립 PNG로 자동 생성합니다. `src/media/stickers.js`의 `STICKERS` 배열에 id·제목·크기·draw를 추가하면 새 위젯을 확장할 수 있습니다. `src/ui/sticker-gallery.js`는 현재 주와 종목·시간을 기준으로 갱신하며, 오래 걸린 이전 렌더가 새 주의 스티커를 덮어쓰지 않도록 버전을 확인합니다. 기존 한 장 이미지는 접힌 보조 메뉴에 유지합니다.

복사할 이미지는 사전에 Blob으로 생성합니다. 복사 클릭 안에서 바로 `ClipboardItem`과 `clipboard.write`를 호출해 Safari의 사용자 동작 조건을 지킵니다. 길게 누르기는 img의 기본 메뉴를 유지하며, 실패 시 PNG 다운로드를 제공합니다. 미리보기의 체크 배경은 CSS일 뿐 파일에는 포함되지 않습니다. OS·브라우저·대상 앱에 따라 이미지 붙여넣기가 다르므로 인스타그램 iOS 실기기 검증은 별도로 필요합니다.
